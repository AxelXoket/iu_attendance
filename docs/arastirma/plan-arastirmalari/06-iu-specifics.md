## 1. AKSIS course roster export (instructor side)

### What was found
- AKSIS is an ASP.NET MVC app at `aksis.istanbul.edu.tr` (login redirect `/Account/LogOn?...AspxAutoDetectCookieSupport=1`,
  checked 2026-09-28). A leaked search-index URL exposes the instructor grade module path:
  `/DersDegerlendirme/DersVeDegerlendirme/GetirSinavOgrenciNotlari?DersGrupID=..&SinavID=..&SinavTipi=2&gridSinavNotGiris-sort=SinavDurumu-asc`
  [CONFIRMED that the route exists; source: search result pointing at aksis.istanbul.edu.tr]. So the instructor
  area is "Ders Degerlendirme > Ders ve Degerlendirme", grades are entered per course group (`DersGrupID`) per exam
  in a grid (`gridSinavNotGiris`) with a `SinavDurumu` (exam status) column.
- The only public AKSIS guide is the **student** OBS guide (`aksis-obs-kullanim-kilavuzu-1.pdf`, BIDB). It has no
  instructor, roster, export or attendance-entry section. [CONFIRMED]
  https://cdn.istanbul.edu.tr/FileHandler2.ashx?f=aksis-obs-kullanim-kilavuzu-1.pdf
- No IU instructor manual (akademisyen / ogretim elemani kilavuzu) for class-list export or attendance entry was found
  on istanbul.edu.tr, cdn.istanbul.edu.tr, bilgiislem.istanbul.edu.tr (CMS API queried directly), IUC's BIDB help
  page, YouTube, Eksi, Sikayetvar or Scribd. [NOT FOUND]
- The official calendar has a line "Sinif Listelerinin Olusturulmasi" (class lists are generated by the system after
  course registration). [CONFIRMED, see section 7]

### Evidence of what IU lists look like (published PDFs derived from AKSIS data)
Headers observed in public IU PDFs on cdn.istanbul.edu.tr (names/numbers deliberately not copied):
| Source file | Header row |
|---|---|
| `grup-7.pdf` | `Sira No / Ogrenci No / Ad / Soyad / Sinif / ...` |
| `adli-tip_637020679832359668.pdf` | `S.NO / OGRENCI NO / ADI SOYADI / IMZA` (one combined name column) |
| `2019yazucders.pdf` | `OGRENCI NO / ADI SOYADI / PROGRAMI / GIRECEGI DERS` |
| ITF `SOLUNUM-UYGULAMA-NOTU.pdf` (2016) | `Ogrenci No / Ad Soyad / UYG NOTU` |
Student number lengths seen: **9 digits and 10 digits, including 10-digit numbers with a leading zero** (e.g. the
`0201......` pattern). [CONFIRMED from the PDFs]

### Conclusion
**A real AKSIS export file is required.** File type (xls vs xlsx vs HTML-disguised-xls vs csv), exact column names,
header offset and encoding could not be confirmed from any public source. [UNVERIFIED]

### Importer must tolerate (derived from the above plus typical ASP.NET grid exports) [INFERRED]
- Formats: `.xlsx`, legacy `.xls` (BIFF8), **`.xls` that is really an HTML table** (common for ASP.NET grid
  "Excel'e aktar"), `.csv` in UTF-8 (with/without BOM) and Windows-1254 (Turkish ANSI).
- Header not on row 1: title rows above the table (course code, course name, group/section, term, instructor),
  merged cells, blank spacer rows, footer rows (totals, print date, "Sayfa 1/2").
- Column-name variants (case/diacritic-insensitive, Turkish-aware case folding for I/i/İ/ı):
  - Number: `Ogrenci No`, `Öğrenci No`, `Öğrenci Numarası`, `Numara`, `No`, `Ögr. No`.
  - Name: either `Adı` + `Soyadı` / `Ad` + `Soyad`, or one column `Adı Soyadı` / `Ad Soyad` / `Adı-Soyadı`
    (split on last whitespace = surname, but keep the original string; compound surnames exist).
  - Optional: `Sıra No`/`S.No`, `Program`/`Programı`/`Bölüm`, `Sınıf`, `Şube`/`Grup`, `E-posta`, `Durum`
    (e.g. first-time vs repeat), `İmza` (ignore).
- **Always treat the student number as text** (leading zeros; Excel may already have stripped them, so allow a
  per-course "pad to N digits" fix and flag 9 vs 10 digit mixes).
- Preserve the uploaded row order (store `roster_order`) so the export can be returned in the same order.
- Re-import must be a merge (add/drop after week 2-4 changes the list; see section 7), never a destructive replace.

## 2. Entering attendance into AKSIS

### Confirmed
- Regulation 2025, Madde 19(3): students failing the attendance requirement "akademik takvimde belirlenen
  yariyil/yil sonu sinavlarinin oncesinde **otomasyon sistemi uzerinden ilan edilir**". [CONFIRMED]
- Every IU calendar has the row "**Ogrenci Devamsizliklarinin Ogrenci Otomasyon Sistemine Islenmesi ve Ilan Edilmesi
  Icin Son Gun**" (deadline for entering absences into the automation system). In the June 2026 draft of the 2026-2027
  calendar that deadline is 20 Aralik 2026 (guz) and 2 Mayis 2027 (bahar), i.e. the day before finals; in the
  updated 4 Aug 2026 version the cell is blank. [CONFIRMED]
- Grade letter `FD` = "Devamsiz Basarisiz" (Madde 21 table and 21(8)(c)). [CONFIRMED]

### Not found
- The instructor screen itself (per-week grid? single devamli/devamsiz flag? total absence hours? a status inside the
  exam grid?). No bulk import is documented anywhere public. [UNVERIFIED]
- The `SinavDurumu` column in the grade grid suggests absence may be recorded as an exam status on the final exam
  entry (like "Devamsiz"), but this is an inference only. [INFERRED, weak]

### Export design that minimizes manual work regardless of which screen AKSIS uses [INFERRED]
Produce one `.xlsx` per course group with:
1. **Sheet "AKSIS" (the one the instructor types from):** rows in the **same order as the uploaded roster**,
   columns `Sira | Ogrenci No (text) | Adi | Soyadi | Devam Zorunlu (E/H) | Toplam Oturum | Katildi | Katilmadi |
   Devam % | Durum` where `Durum` is `DEVAMLI` / `DEVAMSIZ` computed from the 70 % (teorik) / 80 % (uygulama)
   thresholds. Put devamsiz rows visually highlighted.
2. **Sheet "Sadece Devamsizlar":** only students who fail, same columns. If AKSIS needs only a flag on the few
   failing students (most likely given Madde 19(3) wording), this is the whole job.
3. **Sheet "Haftalik":** student x week (or x session) matrix with P/A/R (raporlu) codes and theory/lab split, in case
   the AKSIS screen is per-week.
4. **Sheet "Oturumlar":** session date, hour count, type (teorik/uygulama), cancelled flag.
5. Footer: generation timestamp, threshold used, and the regulation article, so the printout can go into the
   department file.
Also offer CSV (UTF-8 BOM) of sheet 1 for copy-paste. Attendance should be computed in **ders saati** (hours) not
only in sessions, because thresholds are percentages of the course and a 3-hour block missed counts as 3 hours
[INFERRED: common Turkish practice; confirm with faculty].

## 3. Email domains

[CONFIRMED] BIDB "E-Posta Kullanim Talimati" (IU/BIDB/TL-008, first published 30.11.2016) and current BIDB page
(queried via CMS API 2026-09-28):
- Staff: `@istanbul.edu.tr`, only employees and retirees. Students: **`@ogr.iu.edu.tr`**, only IU students.
- Both run on **Google Workspace (Gmail)**. DNS on 2026-09-28: MX of `ogr.iu.edu.tr` and `istanbul.edu.tr` point to
  Google (`aspmx*.google*.com`). [CONFIRMED]
- Student accounts are **not automatic**: the student applies at `https://ogr.iu.edu.tr/` and picks one of the
  **suggested usernames** ("kendisine onerilen kullanici adlarindan bir tanesi"). So the address is **not reliably the
  student number** (secondary sources claiming `ogrencino@ogr.iu.edu.tr` are low-quality Yandex answers). [CONFIRMED
  policy text; exact username pattern UNVERIFIED]
- The same email/password is the **eduroam** credential (`kullaniciadi@ogr.iu.edu.tr`, RADIUS domain `ograd.iu.edu.tr`).
  Students who use campus Wi-Fi therefore have an account. [CONFIRMED]
- Deletion: active students keep the account; graduates' accounts are closed one term after graduation; students whose
  link is cut are deleted without notice. [CONFIRMED, BIDB "E-Posta Silinmesine Iliskin Kurallar"]
- Istanbul University-Cerrahpasa (split 2018) now uses `@ogr.iuc.edu.tr` (also Google MX). Some IUC pages still
  instruct students to get `@ogr.iu.edu.tr`, so **a `@ogr.iu.edu.tr` address does not strictly prove current IU
  enrollment** (legacy/pre-split accounts may exist). [UNVERIFIED]
- Precedent: IU Istanbul Tip Fakultesi ran a **QR + Google Forms** attendance system that required students to be
  signed in with `@ogr.iu.edu.tr` (Google domain restriction), with the form open only the first 2 minutes of class
  (news dated 2021-09-02, guide `qr-kod-ile-online-yoklama-(1).pdf`). [CONFIRMED]

Design implication [INFERRED]: "Sign in with Google" restricted to `hd=ogr.iu.edu.tr` is technically possible and has
local precedent, but (a) not every student has created the account, (b) the Workspace admin (BIDB) can block
unconfigured third-party OAuth apps, so BIDB must be asked. Always match on **student number from the roster**, not on
email; treat email as a verified contact channel only.

## 4. Attendance regulation

Current text: **Istanbul Universitesi On Lisans ve Lisans Egitim ve Ogretim Yonetmeligi**, Resmi Gazete
**28.09.2025 / 33031**, in force from the 2025-2026 year; repealed the 21/9/2010 (27706) regulation (Madde 40).
Primary source read: https://www.resmigazete.gov.tr/eskiler/2025/09/20250928-2.htm [CONFIRMED]

| Topic | Rule | Article |
|---|---|---|
| Threshold | At least **70 %** of courses taken for the first time and at least **80 %** of any practical work outside theory ("35 inci maddede belirtilen durumlar ile ilgili mevzuat hukumlerinde belirtilen durumlar haric") | Madde 19(1) |
| Medicine etc. | Tip, Dis Hekimligi, Eczacilik, Hemsirelik: clinical/practical attendance computed separately per anabilim dali | Madde 19(2) |
| Announcement | Non-compliant students announced **via the automation system before finals**; they cannot sit the final and fail (FD) | Madde 19(3), Madde 26(1)(a)(b) |
| Repeat students | Courses repeated for a reason **other than absence** have **no attendance requirement** (midterm/final still mandatory) | Madde 20(5) |
| Attendance in grade | "ders ve uygulama devami" may be a graded in-term component; weight decided by unit board on instructor proposal | Madde 20(2) |
| Late registration | If a unit board admits a late registration for documented excuse, the missed period **counts as absence** | Madde 9(4) |
| Official duty | Days lost to sports/culture/competition duty are **not counted** as absence | Madde 35(1) |
| Health report (rapor) | Only mentioned for **mazeret sinavi** (midterm make-up, Madde 24(1)(c)) and **kayit dondurma** (Madde 29(1)(a)). No clause excuses absences for a medical report. | Madde 24, 29 |
| Semester length | Guz and bahar, "Bir yariyil, ara sinavlar dahil **on dort hafta**dir" | Madde 14(2) |
| Unit exceptions | ITF, Dis Hekimligi, Hukuk, AUZEF, Eczacilik, Devlet Konservatuvari have separate calendars | Calendar NOT 6 |

Old regulation (2010, amended 2011) had the same 70/80 rule in Madde 19 and required announcement "en gec bes gun
oncesinde"; the 2025 text dropped the five-day wording. [CONFIRMED]

Who decides "devamsizliktan kalma": the regulation uses the passive "ilan edilir"; the instructor records it in AKSIS
before the calendar deadline; the unit's student office publishes. [INFERRED from Madde 19(3) + calendar row;
confirm with faculty]. Raporlu handling: by the text, raporlu days still count toward the 30 % allowance
[INFERRED; the app should record "raporlu" as its own code but count it as absent unless the faculty says otherwise].

## 5. Existing IU attendance systems, apps, Wi-Fi

- **Official IU app**: Google Play `edu.istanbul.mobile`, developer "Istanbul Universitesi", contact
  `developer@istanbul.edu.tr`, 10K+ installs, updated 13 Aug 2026; features: ders programi, **dijital ogrenci kimligi**,
  yemek menusu, duyurular. **No attendance feature listed.** [CONFIRMED from Play listing HTML, 2026-09-28]
  Also `AUZEF Mobil` (com.iu.auzef). One Feb 2026 user review mentions "karekodlu yoklama" negatively; context unclear.
  [UNVERIFIED]
- **Istanbul Tip Fakultesi**: QR code -> Google Form attendance (see section 3), since at least 2018 intern orientation,
  published 2021-09-02. This is the only IU attendance system found. [CONFIRMED]
- No IU-wide electronic attendance system and no report of a failed one was found. The "previous AKSIS-login attempt"
  mentioned by the owner left no public trace. [NOT FOUND]
- Nationally, QR attendance apps at other universities drew press criticism over privacy/KVKK (Cumhuriyet,
  2026-01-10: third-party trackers, location data). Relevant for the privacy notice. [CONFIRMED article; not IU]
- **Wi-Fi**: `eduroam` is WPA2-Enterprise 802.1X, EAP-TTLS/PAP, username = full IU email, password = email password,
  RADIUS server domain `iurad.istanbul.edu.tr` (staff) / `ograd.iu.edu.tr` (students). **No captive portal on
  eduroam.** [CONFIRMED BIDB eduroam page + PDFs]. Whether other SSIDs (guest, open, captive-portal) exist on
  classroom buildings: [NOT FOUND]. Design consequence: students may be on mobile data, not campus Wi-Fi, so
  IP/Wi-Fi-based presence checks are unreliable. [INFERRED]
- IU has a central login portal `giris.istanbul.edu.tr` (SPA, e-Devlet option). No public API/SSO docs. [CONFIRMED
  existence only]

## 6. Name, logo, hosting, app-store risk

- IU **Kurumsal Kimlik Kilavuzu** (Kurumsal Iletisim Koordinatorlugu, 2021) is a visual spec (logo colors RGB
  246/211/48 yellow, 20/113/33 green; templates). No explicit third-party permission clause could be extracted (the PDF
  text is partly glyph-mangled). [CONFIRMED guide exists; permission rules NOT FOUND]
  https://kurumsaliletisim.istanbul.edu.tr/tr/content/kurumsal-kimlik-kilavuzu/kurumsal-kimlik-kilavuzu
- Mass email to all students only after Kurumsal Iletisim approval (BIDB "Toplu e-Posta"). [CONFIRMED]
- No public BIDB procedure for hosting third-party/student apps on IU servers or getting a subdomain was found.
  [NOT FOUND] IU publishes its own apps under the developer account "Istanbul Universitesi".
- **App stores** [CONFIRMED policy text]:
  - Google Play Impersonation policy: bans apps that falsely imply affiliation, e.g. "copying the logo of a business
    entity to falsely suggest it is an official app"; titles claiming official status without permission.
    https://support.google.com/googleplay/android-developer/answer/9888374
  - Apple 5.2.1: do not use third-party trademarks without permission; "Apps should be submitted by the person or legal
    entity that owns or has licensed the intellectual property". https://developer.apple.com/app-store/review/guidelines/
  - Risk: a student-published store app named/branded "Istanbul Universitesi" or using the logo is a likely rejection or
    takedown, and could be reported by IU (which already has an official app). [INFERRED]
- Safe path [INFERRED]: web app (PWA) with neutral name ("... Yoklama", "for IU courses" in description only, no logo)
  until written permission; or have the department/BIDB publish it. KVKK: the app processes student numbers and names
  of IU students, so the data controller question (student vs faculty vs university) must be answered by the university.

## 7. Academic calendar structure

Official source: OIDB CMS accordion (queried via `service-cms.istanbul.edu.tr/api/webclient/GetAccordions`,
group 19936160). Form code IU/OIDB/FR-001/Rev.01/24.08.22. Page numbers below are from the PDFs.

**2026-2027 on lisans / lisans, UPDATED version** (`2026-2027-akademik-takvimi-guncel-hali-(1).pdf`, created
2026-08-04, scanned image, read visually) [CONFIRMED]:
| Item | Guz | Bahar |
|---|---|---|
| Ders alma + danisman onayi | 7 - 25 Eylul 2026 | 25 - 29 Ocak 2027 |
| Katki payi | 7 Eylul - 2 Ekim 2026 | 25 Ocak - 5 Subat 2027 |
| **Ders ekleme-birakma** | **5 - 6 Ekim 2026** | **8 - 9 Subat 2027** |
| Egitim-ogretim | **14 Eylul - 18 Aralik 2026** | **25 Ocak - 30 Nisan 2027** |
| Bitirme sinavlari | 3 - 31 Mayis 2027 (single merged cell for both columns) | same |
| Butunleme | 6 - 27 Temmuz 2027 (merged) | same |
| Devamsizlik entry deadline | blank | blank |

Earlier version (`yeni-2026-2027-...pdf`, created 2026-06-30) had the same 14 Eylul / 25 Ocak teaching dates but
ekle-birak 14-18 Eylul 2026 / 25 Ocak - 1 Subat 2027, class lists generated 14-18 Eylul / 29 Ocak - 2 Subat, midterm
dates into system by 16 Ekim 2026, **devamsizlik deadline 20 Aralik 2026 / 2 Mayis 2027**, guz finals 21-31 Aralik
2026, bahar finals 3-14 Mayis 2027. [CONFIRMED for that draft; superseded]

Conflict: karar.com (2026-08-09) reports guz 21 Eylul - 25 Aralik 2026 and bahar 1 Mart - 4 Haziran 2027. This
contradicts both official PDFs and is treated as wrong. [UNVERIFIED secondary]

2025-2026 (`2025-2026-akademik-takvim.pdf`): guz 22.09.2025 - 26.12.2025, bahar 16.02.2026 - 22.05.2026, ekle-birak
06-07.10.2025 and 23-24.02.2026, finals 03-30.06.2026 and butunleme 13-31.07.2026 as merged cells. [CONFIRMED]

Structural takeaways [INFERRED]:
- Each term is exactly **14 teaching weeks Monday-to-Friday** (14 Eylul -> 18 Aralik; 25 Ocak -> 30 Nisan).
- **Add-drop falls in week 3-4 (guz) / week 3 (bahar)**, after classes start, so rosters uploaded in week 1 will change;
  students who add late legitimately have missed sessions (Madde 9(4) says late-admitted time counts as absence).
- Midterm weeks are set by each unit, not centrally (NOT 5), so sessions must be individually cancellable.
- Public holidays inside terms (e.g. 29 Ekim, 1 Ocak, 23 Nisan, religious holidays) are not in the calendar PDF and
  must come from a separate holiday source or instructor input.
- Six units run their own calendars (ITF, Dis Hekimligi, Hukuk, AUZEF, Eczacilik, Konservatuvar); some are yearly.
- It is now 2026-09-28 (week 3 of guz 2026-2027); add-drop is 5-6 Ekim 2026, so a roster uploaded today should be
  re-imported after 6 Ekim.

   whether it includes e-mail, program, sinif, and first-time vs repeat status.
