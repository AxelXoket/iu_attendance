COMPACT: My recommendations change the moving-part count by about zero. One part is added: an S3-compatible bucket for xprem. It fixes a real gap, because xprem's own docs say local disk is not for production, and MinIO was archived in April 2026. Two parts are removed: the GitHub token read path for release info, and the APK hash field with its client-side hashing step. Every other recommendation is a rule, not a tool.

xprem is still the best fit:
- It is the only self-hosted option that keeps Expo's own client (expo-updates, about 4.85M weekly downloads) and gives signing, percentage rollouts and rollback under MIT.
- Hosted EAS Update would remove the container, but code signing needs the Production plan at 199 USD a month (50K MAU included). The free plan covers 1K MAU and has no signing.
- hot-updater replaces expo-updates with its own native module. It has one dominant maintainer in a user-owned repo and 1.0 is still in release candidates.
- Expo's custom-expo-updates-server says it is a demo, 'not guaranteed to be complete, stable, or performant enough'.
- Writing the protocol into Fastify would rebuild rollouts, rollback and signing by hand.
- Stateless xprem drops the database, but it loses rollouts and brings back an Expo token dependency.

The compact setup is xprem control-plane in a separate database on the existing PostgreSQL server, with in-memory cache (no Redis), no CDN, the dashboard reached only through an SSH tunnel, and a pinned image tag. OTA earns its place mainly for the Android GitHub path (about 77% of phones), where a new APK needs manual installs. AltStore-style sideloading, the Enterprise program and Apple School Manager custom apps are rightly left out.
