COMPACT: Net effect if every recommendation is accepted: 2 fewer dependencies (openapi-typescript and openapi-fetch, both end of life), 1 fewer build step (client generation), 1 fewer CI check (client regenerate-and-diff), 1 fewer future service (Valkey) and 2 fewer named fallbacks (fastify-zod-openapi, Orval). No tool is added. fastify-type-provider-zod is swapped for the official @fastify/type-provider-zod, which has the same exports, so that change is net zero. Everything else is configuration (allowErrorHandlerOverride, --throw-deprecation, trustProxy, rate-limit key, OpenAPI 3.1.0), Biome rules already in the toolchain (noNodejsModules, plus noRestrictedImports as the dependency-cruiser fallback) and Better Auth's built-in openAPI plugin. The only own code added is a small typed fetch helper replacing openapi-fetch, which its own maintainers recommend keeping locally.

Alternatives rejected after an honest comparison:
- oRPC (1.15.4, active but one npm maintainer): adds a second routing and OpenAPI layer on top of Fastify.
- ts-rest (@ts-rest/core 3.52.1): registry metadata untouched since 2025-06-02, so stale.
- Hono RPC: only works by replacing Fastify with Hono.
- @hey-api/openapi-ts (0.99.0): still pre-1.0, with one npm maintainer.
- Switching to Orval (active, 8.40.0 on 2026-10-04): a large code generator that gains nothing in a single TypeScript repo; worth it only if a non-TypeScript client ever appears.

Kept as they are: dependency-cruiser (mature, current, cleanest expression of the boundary rule; dev-only) and @fastify/swagger (official, 8 maintainers; needed for oasdiff and Schemathesis). @fastify/swagger-ui should not be added, because the OpenAPI document is only a CI artifact.
