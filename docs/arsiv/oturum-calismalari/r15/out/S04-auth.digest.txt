F S04-01 [L69 RISK medium] Better Auth's storeOTP 'hashed' mode (which line 586 relies on: 'kod özet olarak saklanır') stores an unsalted, unkeyed SHA-256 of the code. A 6-digit code has only 10^6 values, so anyone who can read the verification table (leaked backup, read-replica credentials, SQL injection elsewhere) can recover a live code instantly, request a code for an instructor and log in within the 5 minutes. The claimed protection is illusory. Both NIST and ASVS say a plain hash is not offline-attack resistant for secrets under 112 bits; they say this for look-up secrets, and the same arithmetic applies here. Better Auth's 'encrypted' mode (key from the server secret) or a custom keyed hash does protect, because the key is not in the database. | URL https://raw.githubusercontent.com/better-auth/better-auth/main/packages/better-auth/src/plugins/email-otp/utils.ts
  REC: Kodu düz özetle değil, sunucudaki gizli anahtarla saklarım: anahtarlı özet (HMAC) ya da Better Auth'ta 'encrypted' seçeneği. 6 haneli kodun yalnız 1 milyon olasılığı var; düz SHA-256 özeti, veritabanını okuyan birine geçerli kodu anında verir.
